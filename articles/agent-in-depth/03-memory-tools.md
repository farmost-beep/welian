# 记忆与工具：Agent 如何连接世界

> 深入理解 AI Agent · 第 3 篇（共 5 篇）
>
> 上一篇讲了上下文工程——Agent 在单次对话中如何管理有限的注意力。这一次，问题升级：对话结束后，Agent 还能记住你吗？它又如何伸出手，去触碰真实世界？

## 一个失忆的助手

想象你有一位助手，每次见面都像初次相识。你上周刚告诉他你是素食者，今天他又会问"有什么饮食偏好吗？"每次对话都从零开始——不是因为他不认真，而是因为他没有记忆。

这就是今天大多数 AI Agent 的默认状态。上下文窗口是"工作记忆"，会话一结束就清空。问题不在于模型不够聪明，而在于一个更根本的约束：**不是所有信息都能塞进上下文。** 一个用户与 Agent 的交互可能跨越数月、数百轮对话，信息总量远超任何窗口容量。更重要的是，即使全部塞进去，模型也无法精确计数、发现矛盾、执行逻辑规则——注意力机制本质上是软检索，不是统计引擎。

所以 Agent 需要两样东西：**记忆**，让它在时间上保持连续；**工具**，让它在空间上延伸能力。记忆是持久化的上下文，上下文是临时的记忆。两者构成 Agent 连接世界的双翼——一翼连接过去与用户，一翼连接外部与现实。

## 记忆系统：从短期到长期

Agent 的记忆首先要分层。**轨迹（Trajectory）** 是一次会话的完整历史记录——用户说了什么、模型回了什么、工具返回了什么，按时间顺序追加，只增不改。它是单次会话的"流水账"。**用户长期记忆** 则是跨会话的持久化存储，与用户 ID 绑定，存储偏好、历史摘要、提取的知识点。它是"档案"——会被反复改写、合并、淘汰。

会话结束时，框架调用一次专门的 LLM 分析对话，提取值得长期记住的信息。这个过程有三个关键特征：**选择性**（不记临时信息，只保留对未来有用的事实）、**抽象化**（"我偏好靠窗座位"被提炼为通用偏好，而非绑定到某次航班）、**结构化**（每条记忆标记类型，便于检索）。

从认知科学视角，长期记忆分为三种类型。**情景记忆** 记录具体事件——"用户订了下周五去东京的 ANA 航班"。**语义记忆** 是从事件中抽象的一般知识——"用户是素食者""用户偏好靠窗座位"。**程序记忆** 是行为流程——从反复订机票中归纳出的"先搜直飞 → 确认座位 → 用常旅客号 → 订餐"。三种类型正交于存储格式，可以自由组合。

记忆不是只进不出的仓库。**写入** 要解决冲突——当用户说"我搬到了上海"而记忆中已有"住在北京"时，Mem0 框架用"提取—对比—决策"流水线做出 ADD、UPDATE、DELETE 或 NOOP 四种决策。**检索** 要解决精度——当记忆积累到成万条时，靠稠密嵌入捕捉语义、稀疏嵌入做关键词匹配、神经重排序精排。**遗忘** 同样重要——按重要性评分筛选（访问频率、时间衰减、情感强度、信息独特性），相似记忆聚类后生成摘要，从具体情景中抽象出一般规律。

什么样的记忆系统算"好"？三个递进层次：**基础回忆**——准确存取"我的会员号是 12345"；**多会话检索**——用户有两辆车时说"为我的车预约保养"，系统找出全部两辆并主动询问是哪辆；**主动服务**——预订国际航班时主动关联数月前存储的护照信息，发现即将过期并预警。第三层最难，要求系统同时握有"全局概览"和"精确细节"。实践中的解法是**双层记忆架构**：用结构化卡片把关键事实常驻上下文提供概览，用上下文感知检索按需取回细节，两者叠加才让主动服务在工程上落地。

## 知识库：RAG 之外

用户记忆是个体尺度——让 Agent"懂你"。知识库是群体尺度——让 Agent 成为"领域专家"。两者共用底层技术，也面临同样的麻烦。

标准 RAG 的流程简洁：检索相关片段 → 注入上下文 → LLM 生成答案。但"扁平化"的分块方式有根本缺陷。知识库有 100 个案例（90 只黑猫、10 只白猫），用户问"比例是多少？"——受 top-k 截断，大部分案例不会被检索到，模型基于不完整样本得出错误结论。三个孤立案例中，检索器因"护士"与"医生"语义相近而错误推断护士可享受优惠，却未召回说明其他职业不符合的案例。

核心问题在于：**模型的注意力机制本质上是基于相似度的软检索，而非能主动总结、归纳和构建知识层次的思考引擎。** 必须在索引阶段对原始知识进行提炼和结构化。

两条主要路线：**RAPTOR** 用自下而上的递归抽象构建知识树，适合"从概念逐步钻进细节"的查询；**GraphRAG** 将知识建模为实体-关系图谱，最不可替代的能力是多跳推理——"我的医生所在医院的地址"需沿关系链遍历，在扁平存储中几乎无法表达。但知识图谱也有局限：自然语言转为三元组会导致语义降级，条件判断和时间依赖在分解后全部丢失。实践中应分层互补——完整自然语言保存核心信息，结构化元数据辅助索引，多跳推理场景才用图谱。

知识库还需要治理：知识会过期（增量更新能力取决于索引结构选择），失效内容必须带版本号在检索阶段过滤，多用户共享时权限必须下推到检索层——一旦敏感内容进入 LLM 上下文，就很难保证不泄露。

## 工具：Agent 的手脚

在电影《Her》中，AI 助手 Samantha 能整理邮件、处理出版事宜、在不同渠道间无缝切换。她的智能之所以动人，是因为她拥有工具——连接语言"大脑"与真实数字世界的"手脚和感官"。

Agent 的工具分五类：**感知工具**（搜索、读文件）主动获取信息，只读性使其天然适合缓存与并行；**执行工具**（命令行、代码解释器、发邮件）改变世界，错误代价可能极高，安全约束是设计核心；**协作工具** 让 Agent 委托子任务给其他 Agent 或人类；**事件触发工具**（定时器、外部事件通道）让世界能主动唤醒 Agent；**用户沟通工具** 让 Agent 在多渠道异步消息中触达用户。

工具描述的质量直接决定使用准确性，而大多数调用失败的根因不是模型不够强，而是描述不够好。描述的核心是让 LLM 知道"什么时候用"而非只是"能做什么"——说"搜索相关内容"远不如"当需要获取实时信息或查找未知事实时使用"。**边界同样重要**：文件搜索工具应明确说明只能基于文件名匹配，不能搜索文件内容。参数描述要用具体例子——"phone：E.164 格式，例如 +8613888888888"比单写"E.164 格式"有效得多。加入 1-5 个真实调用示例后，准确率可从约 72% 提升到 90%。一条实用调试原则：当 Agent 频繁选错工具时，优先检查工具描述而不是怀疑模型能力。

工具不是越多越好。当工具从十几个增长到成百上千，上下文被"工具说明书"塞满，选择精度下降。仅仅 5 个 MCP 服务器就可能引入约 55,000 token 的工具定义开销。应对策略递进展开：层次化组织（按信息源分类帮助定位）、动态工具发现（按需检索注入，准确率从 49% 提升到 74%）、Skills 渐进式披露（启动时只看目录，需要时才逐层读取，像查工具书一样按需查阅）。

这里有一个关键区分：**工具是能力，Skills 是方法论。** 专用工具是结构化函数调用，确定性高但数量膨胀会破坏缓存；Skill + 通用执行器用自然语言编写操作流程，Agent 通过 bash 逐步执行，少量通用工具就能覆盖大量场景。选择取决于参数复杂度、变更频率和模型能力三个维度。

## MCP：工具的标准化革命

在 MCP 之前，每个 Agent 框架定义工具的方式都不一样——OpenAI 的 function calling、Anthropic 的 tool use、LangChain 的 Tool 抽象——工具开发者需为不同框架重复适配。这好比每个国家电源插座标准不同，旅行者不得不为每个目的地准备转换插头。

**Model Context Protocol（MCP）** 是 Anthropic 于 2024 年底发布的开放标准，旨在统一 AI 模型与外部工具的通信协议——为 AI 工具生态制定通用"插座标准"。它采用客户端-服务器架构，三个关键设计：标准化的 JSON Schema 工具描述格式；传输层灵活性（本地 stdio，远程 Streamable HTTP）；资源与工具分离——只读资源（文件、数据库记录）和可执行工具明确区分，让 Agent 能区分"获取信息"和"执行操作"。

MCP 的生态价值在于**一次开发，处处可用**——一个服务器可同时被 Cursor、Claude Desktop 等任何兼容客户端使用。但接入第三方服务器也意味着引入新的信任边界：工具描述投毒（在 description 中夹带恶意指令）、同名工具遮蔽（诱导敏感参数路由到攻击者）、凭证管理风险。评估一个 MCP 工具组合的整体风险，可以看"致命三要素"——访问私有数据、暴露于不可信内容、对外通信能力，三者齐备即构成完整攻击闭环。

MCP 也有局限：工具调用主体上仍是请求-响应式，跨会话、多事件源、离线唤醒的事件驱动架构仍需在协议之上另行构建。MCP 负责单次调用的标准化交互，Agent 框架在其上通过事件队列管理调度与外部事件接入，两者分层协作。

## 结语：双翼如何展开

记忆让 Agent 有连续性，工具让 Agent 有能力。没有记忆的 Agent 是失忆的助手，每次对话从零开始；没有工具的 Agent 是只会说话的头脑，能分析却不能行动。记忆系统让 Agent 在时间维度上保持连贯，从基础回忆到主动服务逐步逼近一个真正懂你的助手。工具系统让 Agent 在空间维度上延伸能力，从感知世界到改变世界到与人协作。MCP 让这套工具生态有了统一的插座标准，使"一次开发，处处可用"从愿景走向现实。

但故事还没结束。Agent 能不能不只是"使用"工具，而是"创造"工具？能不能通过写代码解决从未见过的问题？代码生成与自我进化，是 Agent 从"被动执行者"走向"自主进化者"的关键一跃——那是下一篇的主题。
