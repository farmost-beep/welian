深入理解 AI Agent · 第 4 篇（共 5 篇）

基于李博杰著《深入理解 AI Agent》第 5、7、8 章

2025 年，Cognition Labs 旗下的 AI 软件工程师 Devin 传出以 260 亿美元估值融资的消息。一个成立不到两年的公司，凭什么值这么多钱？答案藏在它做的事情里：Devin 不是帮你补全代码的助手，而是一个能独立接 issue、读代码库、写实现、跑测试、提 PR 的自主编程 Agent。

这个估值背后是一个已被反复验证的判断——代码生成是 AI Agent 目前最成熟、最成功的应用领域。 不是因为代码生成模型特别强，而是因为软件工程几十年积累的基础设施——测试套件、类型系统、版本控制——天然构成了一套强大的"护栏"，让 Agent 能在安全网内大胆试错。

但仅有代码能力还不够。一个真正强大的 Agent 需要经历三重跃迁：先在代码这个最佳战场上证明自己，再通过后训练把通用模型塑造成 Agent 专用模型，最后学会从使用中自我进化——不改动权重，却越用越能干。这篇文章带你走完这条从代码生成到自我进化的完整路径。

一、代码：Agent 的最佳战场

为什么代码是 Agent 最成熟的应用领域？答案可以浓缩为三个词：可验证、可执行、可迭代。

先说可验证。大多数 Agent 任务的验收依赖人工判断——"这篇文章写得好不好"，没有客观标准。但代码不一样：测试套件提供明确的通过/失败信号，编译器告诉你有没有语法错误。Agent 写完代码后，机器自己就能判断对错，形成"写了就测、测了就改"的闭环，不需要人盯着。

再说可执行。你没法"运行"一段话看它对不对，但代码可以。一段能跑通的代码本身就是逻辑自洽的证明。书中用一个数学题说明：纯自然语言推理容易算错，而写成 `phys - both = 18 - 10 = 8` 交给代码解释器执行，结果精确无误。让 LLM 负责理解问题并写代码，让代码解释器负责精确计算——各司其职。

最后说可迭代。Git 提供版本控制和回退能力，沙盒环境提供隔离的执行空间——Agent 可以大胆试错，出错了直接回滚，不必担心不可逆的损失。

书中用"任务清晰度 × 验证自动化程度"的四象限精确定位了代码生成的位置：目标明确且结果可自动验证，是 Agent 发挥的最佳区域。Coding Agent 之所以成熟度高，不是因为代码生成模型特别强，而是因为软件工程几十年攒下的基础设施天然构成了一套强大的 Harness（护栏）。

更深一层，书中提出了一个关键判断：代码不只是工具箱里的一个工具，而是一种"元能力"——能在运行时动态创造新工具和新能力。 遇到数学推理，写段代码交给求解器；缺少某个工具，临时写一个；需要生成 PPT，用代码定义格式。代码生成让 Agent 的能力边界不被预先定义的工具集锁死，而是可以在运行时自主扩展。

这也是为什么从 Manus 到 OpenClaw，成功的通用 Agent 都遵循同一范式：Coding Agent + 文件系统。少量通用工具构建运行时，文件系统是信息流转的枢纽——记忆从文件读取，产物写入文件，经验也保存为文件。

二、从 Copilot 到 Devin：编程 Agent 的三级跳

理解了代码为什么是 Agent 的最佳战场，我们来看编程 Agent 本身是如何演进的。这条路径清晰地分为三个阶段。

第一级：辅助编程（Copilot 模式）。 2021 年 GitHub Copilot 开启 AI 辅助编程时代，核心是代码补全——你写一行注释，它帮你生成接下来的代码。它不理解你的项目结构，不会自己跑测试，价值在于减少打字量和提供灵感，代码正确性完全由人类负责。

第二级：协作编程（Cursor 模式）。 Cursor 把交互从"补全"升级为"对话"——你用自然语言说"把这个函数改成异步的"，它理解意图后修改代码。关键进步在于与代码库建立连接：嵌入索引能在大型代码库中找到语义相关片段，专用 fast-apply 小模型能高效合并变更。但主动权仍在人手里。

第三级：自主编程（Devin 模式）。 Devin 代表质的跃迁——从"辅助"走向"自主"。你给它一个 issue，它自己读代码库、设计方案、写代码、跑测试、修复失败用例、提交 PR。书中描述的理想工作流程正是这个形态：项目文档化 → 需求澄清 → 设计文档 → 代码实现与测试 → 审查与交付，模拟了一个人类工程师的完整工作流。

这里有一个关键的评估认知：编译通过 ≠ 正确。 一个最常见的偷懒方式是 Agent 写完代码不跑测试就报告"任务完成"。书中明确指出，应该把"测试通过"而非"代码写完"定义为完成标准。Coding Agent 的自我纠错能力——测试失败后分析原因、定位问题、修改代码直到所有测试通过——正是把它从代码生成器提升为可靠工程助手的关键。这个"测试-修复"循环可能需要多次迭代，平均 2-3 轮收敛。

Devin 的高估值，本质上押注的就是这条路径的终点：当编程 Agent 的自主性足够高，它就不再是一个工具，而是一个可以按需扩容的"AI 工程师团队"。

三、后训练：从通用模型到 Agent 模型

一个现代模型的能力分三个阶段炼成：预训练在海量文本上做"预测下一个词"，学会语言规律和世界知识——博学但不会好好回答问题；监督微调（SFT）用几千条"问题—标准回答"示范，教会模型该用什么格式和流程回答——变成听得懂指令的助手；强化学习（RL）不再给标准答案，让模型自己尝试、根据结果好坏调整——学会在没见过的情况下也能做出合理决策。

对 Agent 来说，后训练的影响体现在三个关键方向。

第二，多步推理能力。 Agent 的核心是 ReAct 循环——想一步、做一步、看一步，多轮迭代。书中用一组对照实验量化了 SFT 与 RL 的本质区别：SFT 记忆，RL 泛化。在一个算术卡牌游戏中，训练时 J/Q/K 都当 10，测试时 J 变成 11。SFT 模型照旧用 10，出错；RL 模型用同一套策略重新计算，答对。原因在于：SFT 学的是固定映射，RL 学的是可迁移的策略。对于需要泛化到新场景的 Agent 任务，RL 的泛化能力至关重要。

第三，代码生成的专项训练。 代码任务天然适合 RL，因为"验证比生成容易"——代码能跑测试、答案能对照、定理证明器能校验。只要"认出好"比"做出好"容易，RL 就能训出比任何现成示范者都强的模型。书中提到，RL 甚至能发现人类未曾演示过的更优策略——在一个机器人操作实验中，RL 自主发现了"推切"动作，从未在人类演示中出现，却比标准路径更快更稳。

但后训练不是万能的。书中反复强调一条工业界最值钱的经验：数据和环境比算法更重要。 真正决定成败的不是选 PPO 还是 GRPO，而是仿真环境够不够真实、训练数据质量够不够高。如果仿真里的客服总按固定套路回话，模型就会学到一套只在仿真里管用的"应试策略"，一上线就露馅。

还有一个反直觉但极其省钱的判断：很多场景下，只要 SFT 数据质量到位，根本不需要做 RL。 RL 常是 SFT 的几十到上百倍成本，但如果任务分布可预期、能拿到足够多高质量示范数据，扎实的 SFT 往往就够了。

四、自我进化：Agent 学会学习

后训练把能力写进了参数，但改权重需要大量数据和算力，更新周期以周计。而现实中新的 API 上线、旧的服务下线、用户需求不断变化——Agent 需要一种更轻量、更即时的进化机制。这就是第三重跃迁：自我进化。

自我进化的核心思想是"外部化学习"——不改动模型参数，把知识和流程从模型内部和临时上下文中分离出来，外部化为可持久化、可检索、可复用的外部资源。这不是后训练的替代方案，而是互补：后训练解决"如何让模型更聪明"，自我进化解决"如何让 Agent 更能干"。

为什么 Agent 不会自动学习？答案藏在注意力机制的本质里。上下文学习更像检索而非推理——注意力擅长"查找"，不擅长"归纳统计"。把原始经验堆进上下文，模型能"记得"，却不会自动"提炼"成可复用的规律。一句话：学习不会自动发生，必须被显式设计出来。

自我进化有两个维度。

第一个维度：从经验中沉淀知识。 一个客服 Agent 第一次处理某银行的退款流程，花了 15 分钟探索——打了 3 次电话、尝试了 2 种话术——终于成功。如果缺乏外部化学习能力，下次遇到完全相同的请求，只能从头再花 15 分钟。但如果它能把这次经验总结成结构化笔记存入知识库，下次直接检索复用，效率就完全不同了。

书中介绍了多种经验沉淀机制。策略摘要把成功解题过程浓缩为"用了什么方法、踩了什么坑"的经验笔记；工作流录制把重复操作序列固化为可回放的自动化工具——就像 Excel 的宏录制。失败经验同样值得沉淀，甚至信息量更大——一次失败明确排除了一条路径。Reflexion 框架让 Agent 在失败后用自然语言反思原因，存入记忆，下次避免重蹈覆辙。

更精妙的是系统提示词的自动优化。Karpathy 指出，当前 LLM 遗漏了一种重要的学习方式——"系统提示学习"：遇到问题想通了某件事，用明确的语言给自己记下来。它的数据效率远高于强化学习——一次失败只有一个"对/错"信号，而一段自然语言复盘的信息量远大于一个比特。书中介绍了一个航空客服实验：Agent 过度转接人工，人类专家反馈后，Coding Agent 读取系统提示词，生成精确修改——将转接边界明确为"用户明确要求人工 + 紧急安全情况"，添加"绝不因政策争议而转接"的负面规则。优化后原有任务不退化，边界案例正确率显著提升。

第二个维度：从工具使用者到工具创造者。 构建通用型 Agent 时，预定义工具集的假设过于乐观——现实世界需要的工具几乎无限，没法预先枚举。突破在于：Agent 不再被动等待人类准备工具，而是主动寻找、学习、适配和创造工具。

书中以 Alita 系统为例：面对"提取 YouTube 视频字幕"的任务，Agent 不会报告"无法完成"，而是启动自我进化流程——分析需求，搜索开源仓库找到 youtube-transcript-api 库，阅读文档理解 API，封装为标准工具，提取字幕找到答案。新工具保存到工具库，以后类似任务直接复用。

Voyager 在 Minecraft 中把这种理念推向极致：成功完成任务后，动作序列被提炼为可执行代码并持久化存储，技能层次化、可组合——"制作木镐"调用"砍树"和"制作木板"等基础技能。面对新任务时检索和组合已有技能即可快速解决，发现的独特物品数量达到基线方法的 3.3 倍。

五、进化的边界：能改进但不能失控

自我进化赋予 Agent 强大的能力扩展潜力，但也带来了独特的安全风险，需要清晰的边界。

供应链攻击是最直接的威胁。 Agent 自主搜索和安装开源库时，恶意包可能被自动下载执行。缓解措施包括沙盒运行和自动安全扫描。

能力漂移是更隐蔽的风险。 Agent 持续学习积累的策略可能逐渐偏离设计者意图，需要工具类型白名单和定期人工审核。

记忆与经验投毒是最内生的攻击面。 Agent 接触的网页、工具输出可能包含恶意注入指令，未经审查就沉淀为长期记忆，攻击就从一次性变成持久性。缓解手段有三层：写入前审查与来源标记、经验与指令通道隔离、检索时注入检测。

这里有一条不可逾越的红线：Agent 可以改进自己的能力、工具和知识，但不能改变自己的目标。 Agent 身份和行为规则、人类设定的任务目标，必须处于自我进化的权限边界之外。Agent 可以建议规则修改，但增删改必须由人批准。自我进化是能力的增长，不是意志的觉醒——它让 Agent 更能干，但不让 Agent 自行决定"该干什么"。

结语

从代码生成到后训练再到自我进化，我们走完了 Agent 能力跃迁的三级火箭。

代码生成是 Agent 最成功的应用场景，因为软件工程的基础设施天然提供了可验证、可执行、可迭代的环境。后训练是能力塑造的关键，SFT 固化格式，RL 突破泛化，"先形后神"协同工作。自我进化是未来方向，Agent 不改权重却能越用越能干——从经验中沉淀知识，从工具使用者变成工具创造者。

但故事还没讲完。如何科学地评估 Agent 能力？当 Agent 从纯文本走向多模态——能看懂屏幕、听懂语音、操控机器人——架构会怎样变化？多个 Agent 协作时如何分工通信？下一篇，我们将深入评估方法论、多模态感知与多 Agent 协作的前沿实践。
