# Welian 演化研究与三阶段路线图

> **版本**：v3.0.0 路线图研究  
> **日期**：2026-08-01  
> **状态**：已通过独立审查（95/100，无 P0/P1）  
> **方法**：本地仓库只读分析，不涉及线上用户数据

---

## 结论

**Welian 现在不缺功能，缺的是把已经铺开的能力收束成稳定、可信、可衡量的用户闭环。**

建议未来三个阶段依次为：

1. **R1「可信内核」**：收口并形成可发布版本
2. **R2「每周行动闭环」**：证明激活与留存
3. **R3「可解释感知」**：建立真正差异化的网络智能

暂缓新增通道、信号源、企业版、MCP/技能市场和自动社交。

## 二、演化路径

| 阶段 | 主要变化 | 核心判断 |
|---|---|---|
| **1. 原型形成，07-12** | 从官网迅速进入 Phase 1，形成双关系模型和"记/问/拟/报" | 伦理模型与对话场景是最稳定的产品内核 |
| **2. 端云探索，07-12～13** | 边缘—云分离、本地 Agent、Clerk、WebSocket、Tunnel | 连接与认证被过早复杂化，出现多次方向调整 |
| **3. 云优先，07-13** | 方案 C、联点计费、KV 同步、用户隔离、云端 CRUD | 从"必须安装 Agent"转向零安装，是最成功的架构转折 |
| **4. 产品化，07-13～14** | 诚实原则、AGENTS.md、数据飞轮、模拟获客、仪表盘、账单、微信 Bot | 品牌伦理和可配置行为成为差异化资产 |
| **5. 可靠性补课，07-18～19** | SQLite、多用户、Sentry、分层测试、CI、会议闭环 | 测试与运维明显晚于功能扩张 |
| **6. 战略纠偏，07-21～22** | 从"关系操作系统"回到"关系网络智能体"；上线日历、健康分析、年度报告、多源信号和小程序 | v3 放弃平台幻想是正确方向 |
| **7. 当前开发态，07-23～08-01** | SDUI、同步 WebSocket、自进化、订阅消息、社交图谱、邀请码、ego-browser 感知 | 再次出现同时扩展产品、协议、数据与智能层的迹象，尚未达到发布状态 |

### 演化中的三个核心规律

1. **真正稳定的是产品伦理，不是具体架构。**  
   双关系模型一直保留，且明确禁止对陪伴型关系做功利计量。

2. **成功的变化都在降低使用门槛。**  
   云优先、小程序和对话输入有效；Tunnel、平台生态和多套并行入口则增加复杂度。

3. **主要反模式是"能力先铺开，验证后补"。**  
   历史中有 93 个 `fix`、77 个 `feat`；发布标签后继续积累 140 个提交，当前 Worker 又增长至约 1.46 万行。

## 三、当前状态诊断

### 已有优势

- 产品定位已经稳定为"关系网络智能体"，而非关系数据平台。
- "记/问/拟/报/会"覆盖了完整的关系行动过程。
- 双关系伦理、诚实原则、主动信号和中国微信生态形成了组合差异。
- 已经具备日历订阅、关系健康、年度报告、多源信号、自定义 RSS、支付和多通道触达，不需要继续横向扩功能。

### 需要优先处理的问题

#### 1. 当前开发态未过质量门

- Vitest：**488 项中 1 项失败**
- pytest（`PYTHONPATH=src`）：**83 项中 1 项失败**
- ESLint：**36 个错误、61 个警告**
- Playwright：仅列出 **66 项 Web journey**，本次未执行，也不覆盖新的小程序 SDUI/WebSocket 真机主链路

其中 lint 已发现 `thinkingId`、`session`、`clerkUserId` 等未定义变量，因此不只是风格问题。

#### 2. 数据可信风险高于功能缺口

KV 当前以整组数组读取和覆盖写入；JSON 解析失败时静默返回空数组，后续写入可能把异常数据覆盖为空。

此外，多通道同时更新联系人、待办和时间线时，没有显式版本控制或冲突检测，存在丢失更新风险。

#### 3. 日历订阅无法单用户撤销

日历 token 为 `userId:WELIAN_SYNC_SECRET`，后半段是全局环境 secret。当前若要撤销一个用户，只能轮换全局 secret，从而影响全部订阅。

#### 4. "无感社交图谱"与产品伦理冲突

联系人分享 URL 直接携带联系人姓名和邀请者 openid。后端随后把点击者 openid "无感"绑定到分享者的联系人记录。这不应作为默认功能发布：身份关联应使用不含姓名的 opaque ID，并要求双方显式确认。

#### 5. Cron 配置与处理逻辑不一致

`wrangler.toml` 配置了每日 `01:00 UTC` 的任务，注释称用于关系冷却。但 Worker 只处理周一 `01:00 UTC`；每日任务会命中 fallback，实际执行周报推送。

## 四、未来三个阶段

### R1「可信内核」

**目标用户：** 现有用户与封闭测试者  
**产品承诺：** 记/问/拟/报/会在 Web 和小程序都稳定运行，数据可恢复、隐私可控。

#### 必做功能

1. **明确各端职责**
   - 小程序：主交互入口
   - Web：获客、深度管理和报告
   - Bot：快速记录和提醒
   - 本地 Agent：感知、文件和本地能力的可选增强

2. **限制 SDUI 使用范围**
   - 先用于周报、月报、信号、隐私等只读页面
   - 联系人、待办、聊天等有状态主链路继续使用原生页面
   - 等协议测试和真机旅程稳定后再扩大范围

3. **恢复完整质量门**
   - Vitest、pytest 全绿
   - ESLint 0 error
   - 新增小程序阻断旅程：登录 → 添加三位联系人 → 记互动 → 获得建议 → 完成待办 → 收到提醒
   - 修复 Cron 映射及当前未定义变量

4. **建立数据恢复能力**
   - 数据集版本号、幂等键和冲突检测
   - 定期快照、用户导出、恢复演练
   - JSON 解析失败必须报警并停止覆盖写入
   - 日历改用每用户随机、可撤销 token

5. **完成隐私收口**
   - 停用"无感 social_graph"
   - 分享链接改为 opaque report ID
   - 身份绑定必须双方确认，并支持撤销

6. **建立发布看板**
   - 写入失败率、端点错误率
   - 首个价值时间
   - 核心关系行动数
   - 信号源健康度
   - 通知授权与退订

#### 退出门

- 确定性测试全绿、lint 0 error
- 小程序关键真机旅程通过
- 数据恢复演练通过
- 所有身份关联均有显式同意
- 激活与行动漏斗可完整采集

**明确不做：** 新通道、新信号源、新套餐、关系图谱 UI。

---

### R2「每周行动闭环」

**目标用户：** 优先聚焦销售、BD、创业者等关系密集型用户  
**产品承诺：** 每周至少帮助用户完成一件由本人确认的关系行动。

#### 必做功能

1. **三联系人快速激活**
   - 名片扫描、导入、语音记录任选一种
   - 设置关系类型和当前目标
   - 立即生成第一条基于真实数据的建议

2. **统一行动闭环**
   - 信号、会议、到期待办进入同一流程：
   - 为什么现在 → 建议聊什么 → 用户确认草稿 → 用户自行发送 → 记录结果 → 生成跟进

3. **克制的主动触达**
   - 从现有 `todo_due` 扩展到会议前、重要日期和周报就绪
   - 提供频率、静默时段和关闭控制
   - 不做默认每日轰炸

4. **可解释自进化**
   - 展示"学到了什么、依据哪些记录、改变了什么建议"
   - 支持编辑、删除和重置
   - 不把隐藏 prompt 注入当成用户可感知的进化

5. **留存通过后再做裂变**
   - 邀请码和分享能力可以保留
   - 邀请奖励仅在激活、留存门槛达成后开启，避免放大一个留不住人的产品

#### 退出门

沿用现有规格作为目标，而非现状成绩：

- 首个价值中位时间 `<3 分钟`
- 7 日激活率 `≥40%`
- D30 留存 `≥20%`
- 建议到关系行动转化 `≥15%`

**明确不做：** 自动发送、陪伴型冷却或排序、团队协作、更多信号源。

---

### R3「可解释感知」

**目标用户：** 已达到数据密度门槛、主动开启感知的留存用户  
**产品承诺：** 不仅记得过去，还能带出处地发现对方的新变化，并转化为用户确认的行动。

#### 必做功能

1. **从低风险来源试点**
   - ego-browser 先做手动触发
   - 首批使用 GitHub 和用户指定网页
   - 暂不批量、定时采集 LinkedIn/Twitter

2. **证据优先**
   - 每条感知必须展示来源、采集时间、原文和置信度
   - 用户确认后才写入记忆或时间线
   - 支持纠错、删除和撤销

3. **显式关系网络**
   - 只使用用户录入或确认的连接
   - 先提供引荐路径和会前协作图
   - 不公开关系评分
   - 不对陪伴型关系计算路径、冷却或价值

4. **实验 next-best-action**
   - 仅根据确认事实生成
   - 用户决定是否采用
   - 永不自动发送消息

5. **按质量扩展传感器**
   - 只有来源健康、准确性和行动转化达标后，才扩大来源与自动频率

#### 退出门

- 100% 感知卡具有出处
- 用户确认准确率 `≥90%`
- 错误写入可完全撤销
- 感知到有用行动转化 `≥20%`
- 无未经同意的身份关联

**明确不做：** 陌生人发现、批量爬取、自动社交、技能市场、MCP 平台化。

---

## 五、最终优先级

> **R1 数据可信与质量门 > R2 激活、行动与留存 > R3 感知与网络智能**

如果下一个版本只能完成一件事，不应增加新功能，而应把当前小程序核心旅程变成一个**有真机测试、有恢复能力、有完整漏斗数据的可发布版本**。
